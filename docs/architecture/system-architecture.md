# 系统架构

## 1. 定位

`java-agent-platform` 是一个 AI 智能体平台：用户在 Web 端发起对话或检索请求，
由后端智能体服务编排模型调用、工具调用与外部检索能力，并统一管理用户、项目、会话历史与长期记忆。

本文档描述**目标架构**。骨架阶段只落地了工程结构与配置模板，业务实现见 README 的「后续阶段」。

## 3. 技术选型

| 层次 | 技术 | 版本 | 说明 |
| --- | --- | --- | --- |
| 前端 | Vue / Vite / TypeScript | 3.5 / 6 / 5 | SPA，Pinia 状态管理，Vue Router 路由 |
| 网关 | Spring Cloud Gateway (WebFlux) | 5.0.0（随 SC 2025.1.0） | 统一入口、路由、跨域 |
| 服务框架 | Spring Boot | 4.0.0 | 根工程统一版本管理 |
| 微服务 | Spring Cloud / Spring Cloud Alibaba | 2025.1.0 / 2025.1.0.0 | 服务发现、配置中心、OpenFeign、LoadBalancer |
| AI 能力 | Spring AI | 2.0.1 | OpenAI 兼容模型接入 |
| 存储 | MySQL / Redis | 8.4 / 7.4 | 业务数据与长期记忆 / 会话短期记忆与缓存 |
| 注册配置 | Nacos | 2.4.3（服务端） | 注册中心 + 配置中心 |
| 运行环境 | JDK / Maven | 17 / 3.9.x | 编译目标 17 |

## 4. 部署形态

- **本地开发**：基础设施（MySQL / Redis / Nacos / Nginx）由 `docker-compose.yml` 提供，
  后端服务在 IDE 中启动，前端由 Vite 开发服务器提供（`/api` 代理到网关 8080）。
- **后续演进**：为各服务补充 Dockerfile，纳入同一 compose 编排，Nginx upstream 改为 `gateway-service:8080`。

## 5. 关键约束

1. 版本只在根 `pom.xml` 的 `properties` 中维护，子模块不写版本号。
2. 所有可变配置走环境变量，禁止把密码、密钥写进代码或配置模板。
3. 服务间调用只允许经网关对外暴露，内部调用通过服务名（`lb://service-name`）+ Nacos 发现。
4. 公共代码下沉到 `backend/common/*`，业务服务不得互相直接依赖（只能依赖 `common-api` 中的接口定义）。
